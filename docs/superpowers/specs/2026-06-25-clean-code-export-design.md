# 纯净代码导出工具设计

- 日期：2026-06-25
- 项目：docshop
- 主题：导出去除测试与部署无关内容的纯净代码

## 1. 目标

提供一个 Python 导出程序，从以下源目录导出可部署代码：

- 源目录：`C:\Users\lihuo\Desktop\docshop`
- 输出目录：`C:\Users\lihuo\Desktop\新建文件夹 (2)`

导出结果用于部署，因此需要：

1. 去掉测试相关内容
2. 去掉部署无关杂项
3. 保留正式源码、正式依赖、必要配置与部署脚本
4. 每次执行前先清空输出目录，再重新导出

## 2. 已确认决策

### 2.1 导出范围

采用 **B 模式**：

- 去掉测试相关内容
- 去掉部署无关杂项

不采用“仅去测试”，也不采用“极限白名单仅保留最小运行集”。

### 2.2 输出策略

采用 **覆盖式全量导出**：

1. 删除 `C:\Users\lihuo\Desktop\新建文件夹 (2)` 下现有内容
2. 重建输出目录
3. 重新导出一份新的纯净代码

## 3. 方案选择

采用 **规则驱动导出**。

即：脚本内部维护一组集中定义的排除规则，遍历源目录时根据规则决定“复制”或“跳过”。

选择该方案的原因：

- 当前项目同时存在后端、前端、测试、日志、缓存、构建产物、zip、数据库等多类内容
- 单纯硬编码 if/else 可维护性差
- 白名单方案虽然最干净，但当前项目容易漏掉真实部署所需文件
- 规则驱动方案能兼顾稳定性、可维护性和后续扩展性

## 4. 导出边界

### 4.1 必须保留

保留以下类型内容：

- 后端正式运行源码
- 前端正式运行源码
- 正式依赖文件
- 正式运行配置
- Docker / 部署 / 启动相关脚本
- `.env.example`

#### 测试相关

- `test/`
- `backend/tests/`
- `frontend/e2e/`
- `frontend/src/test/`
- 任意 `__tests__/` 目录
- `*.spec.*`
- `*.test.*`
- `pytest.ini`
- `backend/pytest.ini`
- `vitest.config.js`
- `playwright.config.js`
- `requirements-dev.txt`
- `requirements-loadtest.txt`

#### 部署无关杂项

- `.git/`
- `.codegraph/`
- `.pytest_cache/`
- `node_modules/`
- `frontend/node_modules/`
- `frontend/dist/`

- `docs/`
- `logs/`
- `*.log`
- `*.pid`

  - `*_test*.db`

  - `_tmp*.db`

## 5. 脚本行为设计

建议脚本位置：

- `scripts/export_clean_code.py`

建议行为：

1. 校验源目录存在
2. 校验输出目录父路径存在
3. 清空输出目录现有内容
4. 重建输出目录
5. 遍历源目录
6. 按规则跳过不需要的目录和文件
7. 复制剩余文件到输出目录
8. 输出导出摘要

## 6. 规则匹配设计

脚本应至少支持以下判断维度：

1. **目录名排除**：如 `tests`、`__tests__`、`node_modules`、`logs`
2. **相对路径排除**：如 `backend/tests/`、`frontend/e2e/`
3. **文件名模式排除**：如 `*.spec.js`、`*.test.py`、`*.log`
4. **精确文件名排除**：如 `pytest.ini`、`vitest.config.js`

规则顺序以“排除优先”为准；命中任一排除规则即跳过。

## 7. 输出结果设计

脚本执行完成后，应至少输出：

- 源目录
- 输出目录
- 已复制文件数
- 已跳过文件数
- 已跳过目录数
- 主要排除原因统计

如实现成本低，建议同时写出一份摘要文本，例如：

- `export_summary.txt`

该摘要文件放在输出目录根部，便于部署前复查。

## 8. 错误处理

需要覆盖以下情况：

1. 源目录不存在：直接报错并退出
2. 输出目录无法删除或创建：直接报错并退出
3. 个别文件复制失败：记录失败项，并在最终摘要中体现
4. 路径包含中文和空格：必须正确处理
5. 输出目录位于源目录之外：当前场景满足，仍应显式按绝对路径处理

## 9. 测试策略

实现阶段采用 TDD。

优先验证以下行为：

1. 命中测试目录时会被排除
2. 命中 `*.spec.*` / `*.test.*` 时会被排除
3. 正式源码文件会被保留
4. 导出前会清空输出目录
5. 复制后目录结构与源目录相对结构一致
6. 中文与带空格路径可正常处理

测试不直接操作真实项目目录，优先使用临时目录构造最小样例。

## 10. 非目标

本工具当前不负责：

- 自动安装依赖
- 自动构建前端
- 自动打包为 zip
- 自动判断“线上一定可运行”
- 自动分析每个文件是否真正被运行时引用

其职责仅为：**按约定规则导出一份更适合部署的纯净代码副本**。

## 11. 实施后验收标准

满足以下条件视为完成：

1. 运行脚本后，输出目录被重建
2. 输出目录中不包含测试相关内容
3. 输出目录中不包含日志、缓存、coverage、zip、测试数据库等部署无关内容
4. 输出目录仍保留后端/前端正式源码与必要配置
5. 脚本打印清晰摘要
6. 相关自动化测试通过
